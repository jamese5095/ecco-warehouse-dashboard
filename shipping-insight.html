1订单接收确认WMS接收EDI；核对邮件与系统信息；对需人工导入的订单导入Excel明细。订单数、SKU数和数量保持一致。

3 订单类型差异 Order Types

三类订单对效率、准确性与包装精度的要求不同，不能使用同一套作业尺度评价
维度主单补单2C订单
订单特点批量大，整箱为主数量分散，按件处理单件或小批量，多平台
拣货方式按波次批量整箱拣货人工按件拣货按款号、尺码和订单拣货
系统操作按箱批量处理，相对标准化人工核对较多，操作更灵活关注面单及订单状态
包装要求粘贴发运标签鞋、服装和配饰分类包装精细包装、平台附件与逐件称重
主要风险漏箱、错箱错拣、漏拣及异常混放错发、包装瑕疵及消费者投诉

4 洞察一 · 临时仓拣货可达性 Layout

托盘摆放更重视存储密度，目标箱位于内侧时需要移动整托才能完成扫码和拣选
flowchart LR A[托盘紧密摆放] --> B[目标箱位于托盘内侧] B --> C[无法直接靠近扫码] C --> D[拖拽整托移位] D --> E[定位并拣选目标箱] E --> F[整托复位] D --> R1[增加无效动作] D --> R2[增加体力与安全风险] D --> R3[延长按箱拣货时间] style D fill:#d1242f,color:#fff
观察成因作业影响改善方向
托盘间距小，箱码统一朝外，但内侧货箱不可直接触达。布局优先追求临时存储密度，未充分考虑拣货员侧身、扫码和取箱空间。增加拖托、复位和重复定位动作，同时带来搬运安全风险。现场测量后定义最小操作间隙；将“可扫码、可侧身、可取箱”纳入托盘摆放标准。
✅ 可落地建议：不直接设定未经验证的固定间距，先按人员、托盘和扫码动作完成现场测量，再形成临时仓摆放红线与操作通道标准。

5 洞察二 · 异常处理链路过长 Exception

补单错拣后的处理跨越查询、暂存、归位、重拣和盘点，多次人工传递增加二次差错概率
flowchart LR A[发现拣货错误] --> B[盘点人员查询原库位] B --> C[错误商品暂存工作区] C --> D[归还原库位] D --> E[查询正确商品库位] E --> F[重新拣货] F --> G[库存盘点确认] C -.混入正常货物.-> R[二次错拣风险] style C fill:#f0883e,color:#fff style R fill:#d1242f,color:#fff

建议的异常闭环

  1. 设置异常隔离区：错误商品不得继续放在正常工作区或待发货区域。
  2. 实行一件一标识：标明原订单、SKU、错误原因、当前状态和责任人。
  3. 系统生成退回任务：通过扫码引导归位和重新拣货，减少人工查询及口头交接。
  4. 记录异常根因：按SKU、库位、波次和错误类型汇总，识别高频差错来源。
改善目标：不仅缩短异常处理时间，更要避免异常商品与正常货物混放，使每件异常商品始终处于可识别、可追踪的状态。

6 仓运协同与履约传导 Supply Chain

仓库完成装车只代表实物责任转移，客户履约仍沿运输、渠道或终端消费者继续向下延伸
flowchart LR A[仓库发货] --> B[司机点数与单据签署] B --> C[物流运输] C --> D{订单去向} D -->|主单/补单| E[B端渠道履约] D -->|2C| F[终端消费者履约] E --> G[缺货与渠道销售风险] F --> H[退货、差评与售后成本] style A fill:#238636,color:#fff style G fill:#d1242f,color:#fff style H fill:#d1242f,color:#fff
供应链议题当前观察建议方向
仓运责任交接仓库与司机点数、留存四联单后完成责任转交。多仓统一暂存、点数、签单和责任边界标准，减少货损与丢失争议。
运输资源协同发货进度主要同步给ECCO，运输端信息联动有限。将预计货量、发运时间和车辆需求提前同步承运商，减少待发区积压和车辆等待。
B端履约风险主单、补单错发漏发可能造成下游客户缺货。以订单准确率和完整交付率共同评价发货质量。
2C体验风险包装瑕疵或错发直接影响消费者体验。加强面单、商品、附件、包装和称重的一致性校验。
优先改善 01异常隔离与系统闭环

先降低二次错拣和库存差异风险。

优先改善 02临时仓可达性标准

减少拖托、复位等无效动作。

协同建设 03仓运交接标准化

明确数量、单据与责任转移边界。

协同建设 04发货信息向运输端延伸

用预计货量支持车辆资源安排。

💡 总结：发货岗的价值不只是“把货发出去”，而是以准确、及时、包装合规、交接清晰和信息可追踪的方式，完成从仓内作业到供应链履约的连接。
